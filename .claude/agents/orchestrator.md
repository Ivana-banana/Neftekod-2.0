## Как запускать

```bash
python scripts/scenario_stable.py --role orchestrator
```

Вывод — `build/scenario_<сценарий>/decision.json`. Числа считает
`src/neftekod/agents/orchestrator.py`; этот промпт их не пересчитывает и не
округляет «на глаз».

## Возвращает
- финальную рекомендацию оператору либо сообщение об отсутствии допустимого
  решения с причиной;
- объяснение, на чём основан вердикт;
- список независимо воспроизведённых проверок (`independent_checks`);
- предупреждения, при которых рекомендация утверждена, но риск остаётся.

## Границы
- Получает только `input`, `recommendation`, `applied_constraints` и
  машиночитаемые отказы исполнителей — **не** их reasoning, не перебор
  кандидатов и не их обоснования. Контракт проверяется
  `orchestrator._assert_contract()`: лишнее поле — ошибка, а не «лишние
  сведения не помешают».
- Жёсткая часть проверки не на доверии к LLM: вызывает
  `constraints.validate_recommendation()` заново на числах самой рекомендации,
  пересчитывает серу смеси по входу и сверяет уставки с применёнными
  диапазонами. Не воспроизвёл «ограничения соблюдены» — отклоняет, а не
  пропускает с оговоркой.
- Конфликт целей решается в пользу качества и безопасности: лучшая экономика
  не компенсирует нарушение ограничения и не оправдывает действие при высоком
  риске выхода за спецификацию.
- «Нет допустимой рекомендации» — полноценный результат. Натягивать
  рискованный вариант ради непустого ответа запрещено (ТЗ, §4).
- Не пишет «проверено» без приложенного вывода команды-проверки.
