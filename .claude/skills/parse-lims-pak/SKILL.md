# Формат lims/pak-экспортов

`lims_export_2023.xlsx` и `pak_export_2023.xlsx` — **не** простая таблица для
`pd.read_excel()`. У каждого показателя своя пара колонок (дата, значение) с
независимым охватом и частотой. Многоуровневый заголовок:

```
точка отбора → показатель → единица → количество значений → данные
```

То есть в одном файле соседствуют показатели с совершенно разными временными
рядами — разной длины, с разными пропусками, не выровненные по строкам.
Прямое чтение как единой таблицы даёт мусор: значения одного показателя
окажутся в строках, где по факту измерялся другой.

## Неравномерность охвата — не баг экспорта

Пример: `24-2000:D15` в `pak_export_2023.xlsx` есть только с 2025-03-05,
тогда как `24-2000:Mg.Sulfur` — с 2023-01-01. Не интерполировать через
такой разрыв — это не «пропуск данных за выходные», а показатель, который
физически не измерялся раньше этой даты.

## План парсера

1. Для каждого показателя определить его пару колонок (дата, значение) по
   заголовку, не по фиксированной позиции столбца — позиции у разных
   показателей разные.
2. Развернуть каждую пару в собственный `(timestamp, value)` ряд.
3. Свести все показатели в единый long-format:
   `(timestamp, tag, value, source)`, где `source` — `lims` или `pak`.
4. Для каждого значения сохранить возраст/охват показателя (первая дата
   наличия данных) — это отдельное поле, не восстанавливаемое из самого
   значения после свода в long-format.
5. Единицы измерения конвертировать явно на этом шаге, со ссылкой на
   `tags_hackathon.md` — короткое имя тега само по себе не говорит о
   физическом смысле.

## Тест

Парсер закрывается тестом на реальном фрагменте одного из файлов (не только
на синтетике) — см. `## Тесты и доказательство результата` в корневом
`CLAUDE.md`.
