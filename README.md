# Нефтекод 2.0 — МАС рекомендаций оператору (гидроочистка → блендинг ДТ)

## Что это

Мультиагентная система, которая на замороженный момент времени берёт реальные
данные установки 24-2000 (телеметрия, ЛИМС, ПАК), оценивает качество товарного
дизельного топлива и режим установки, перебирает управляющие воздействия и
выдаёт оператору **проверенную рекомендацию или обоснованный отказ** — в виде
карточки по семи блокам ТЗ §5 и машиночитаемых JSON.

Четыре роли — детерминированные Python-модули без LLM и без внешних вызовов
(закрытый контур, см. `CLAUDE.md`): **агент качества** → **агент надёжности**
→ **агент оптимизации** → **оркестратор**, который получает только пакет
(вход, рекомендация, ограничения) и **заново** воспроизводит каждую проверку
по независимым источникам. Взаимодействие ролей — в `src/neftekod/scenarios.py`
и в файлах `build/scenario_*/`.

## Какую проблему решает

Сера в товарном ДТ должна быть ≤ 10 мг/кг (задано организаторами), T95 ≤ 360 °C,
цетановое число ≥ 51, плотность 820–845 кг/м³ (ГОСТ, параметры сценария), доли
блендинга = 100 %. Анализы ЛИМС редкие (раз в сутки, публикация +4 ч), ПАК
может залипать, телеметрия — с дефектами. Система должна не нарушать жёсткие
ограничения ни ради какой экономики, честно различать *проверенный историей
прогноз* и *модельную оценку эффекта действия*, и отказываться, когда данных
нет.

## Быстрый старт

Нужны Python 3.11–3.14 (проверено на 3.12 и 3.14) и `unrar` либо `7z`.

```bash
# 1. Установка (из корня репозитория, ~1 мин)
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

# 2. Телеметрия (не в git). По ссылке лежит архив data.rar (96 МБ):
#    https://drive.google.com/drive/folders/1nH7mdXxdGIvv8Rp6g170xSrUggMfpN4L
#    Распакуйте его в корень репозитория — появится data/ с двумя CSV:
7z x data.rar          # или: unrar x data.rar
ls data/               # 242000_tags.csv (87 МБ) — обязателен; avt_tags.csv (236 МБ) — только для сверки справочника

# 3. Полный цикл (~15 с)
python scripts/prepare_data.py        # ЛИМС/ПАК xlsx → build/lims_pak_long.csv, tag_map.csv, coverage_report.*
python scripts/evaluate_forecast.py   # backtest прогноза серы → build/forecast_report.csv/.md
python scripts/run_all_scenarios.py   # 4 сценария → build/scenario_*/recommendation.md + JSON

# 4. Тесты
pytest -q                             # 336 passed
```

Без телеметрии работают `prepare_data.py` и `pytest` (часть тестов
пропускается); `evaluate_forecast.py` и `run_all_scenarios.py` завершаются с
кодом 1 и называют недостающий файл.

Скрипты не зависят от текущего каталога (пути от `Path(__file__)`); `build/`
создаётся автоматически. Случайности в прогоне нет: два запуска подряд дают
побайтово одинаковые файлы (проверено `md5sum build/scenario_*/*`, 28/28, в том
числе между Python 3.12 и 3.14).

## Как работает

```
lims_export_2023.xlsx ─┐  prepare_data.py   build/lims_pak_long.csv (timestamp, available_at, unit…)
pak_export_2023.xlsx  ─┘                    build/tag_map.csv, coverage_report.*
data/242000_tags.csv ──── evaluate_forecast.py ── build/forecast_report.csv  (backtest, split=test)
                                   │
   scenarios.execute(окно, момент выдачи)  ── context.json  (снимок as-of, возраст каждого значения)
     ├─ агент качества      → quality.json      прогноз серы, риск, измеренные T95/ЦЧ/плотность/сера,
     │                                          аномалии входа, залипший ПАК, доверие к данным
     ├─ агент надёжности    → reliability.json  индекс тяжести режима (прокси), останов установки,
     │                                          модельные диапазоны p05–p95 для оптимизации
     ├─ агент оптимизации   → optimization.json 12 кандидатов (hold, 5 долей блендинга, 6 уставок),
     │                        submission.json   причина отклонения каждого, evidence_type у каждого
     └─ оркестратор         → decision.json     26 независимых проверок по пакету и источникам,
                              recommendation.md вердикт approved / rejected / no_admissible_recommendation
```

- **Синхронизация только по времени** (`features.py`): для каждого момента
  выдачи берётся последнее измерение с `timestamp ≤ t − lag`; ЛИМС/ПАК —
  только при `available_at ≤ t` (ЛИМС: отбор + 4 ч). Возраст каждого значения
  сохраняется, пропуски не интерполируются.
- **Разбиение по времени** (ADR-006): train ≤ 2025-12-24, зазор 7 суток, test
  с 2026-01-01; зафиксировано до обучения. Тест `test_no_feature_leakage`
  проверяет отсутствие утечки из будущего.
- **Прогноз серы** (ADR-012): сдвинутый persistence `0.3·последний анализ +
  0.7·уровень train`, shrinkage выбран на valid по MedAE. Ridge по телеметрии
  (P8, T11, F19, лаги 0–3 ч, alpha на valid) оценивается тем же backtest и
  проигрывает — поэтому изменение уставок не сертифицируется.
- **Жёсткие ограничения** (`constraints.py`, ADR-015…019): проверяются и у
  прогноза, и у *измеренных* показателей продукта; «не подтверждён» ≠
  «нарушен» (ADR-017): неподтверждённый показатель блокирует любое изменение,
  но не статус-кво; доказанное нарушение блокирует всё, включая `hold`.
- **Выбор действия** (ADR-010, ADR-019): кандидат допустим, если проходит все
  жёсткие проверки, не строится на аномальном входе и — если он уменьшает
  запас по сере — оставляет запас ≥ backtest-RMSE. При риске `high` среди
  допустимых выбирается наибольший запас по сере, иначе минимальная стоимость.
  Экономика никогда не делает вариант допустимым.
- **Оркестратор** сверяет пакет не сам с собой, а с выводами агентов качества и
  надёжности, снимком данных, показателями компонента, разрешёнными из данных
  отдельно, и постановкой блендинга (ADR-010, ADR-019); подделка любого поля
  пакета даёт `rejected`.

Все решения с обоснованием — в `docs/adr/` (ADR = architecture decision
record; свежие уточнения в начале файла имеют приоритет).

## Результаты

Прогон 2026-09-22 (`python scripts/run_all_scenarios.py`):

```
  сценарий      момент выдачи        риск качества  запас, мг/кг  severity  кандидатов  допустимых  рекомендация                   вердикт
  stable        2026-02-04 12:00:00  high           1.46          0.045     12          1           hold                           approved
  quality_risk  2026-05-12 14:00:00  high           1.01          0.124     12          1           hold                           approved
  stale_data    2026-06-25 09:00:00  отказ          —             1.000     0           0           —                              no_admissible_recommendation
  full_cycle    2026-04-04 20:00:00  high           2.33          0.068     12          2           blend_straight_run_240_350_f0  approved
```

| Сценарий | Что показывает | Итог |
|---|---|---|
| 1 `stable` — самая спокойная неделя test | нет лишних действий | `hold`; плотность продукта не подтверждена (анализу 50 ч при пороге 48) → изменения заблокированы, статус-кво с пометкой |
| 2 `quality_risk` — рост серы 3.2 → 9.9 за 72 ч | риск качества | `hold` с предупреждением: запас 0.26 мг/кг у текущего состава; ЦЧ продукта не подтверждено (61 сут) — изменение состава не сертифицируется |
| 3 `stale_data` — середина разрыва ЛИМС 350 ч | неполные/устаревшие/аномальные данные | отказ с названной причиной: ЛИМС 179 ч, **ПАК залип 7 суток** (возраст 0 ч, одно число), **установка остановлена** (T11 = 27.7 при ~360) |
| 4 `full_cycle` — наибольший запас по сере | полный цикл до рекомендации | **`adjust_blend`**: снизить долю модельного прямогонного компонента 0.0074 % → 0; сера смеси 8.37 → 7.67 мг/кг; все четыре показателя подтверждены; 26/26 проверок оркестратора |

Окна и моменты выдачи заморожены до правки моделей (ADR-010, ADR-011) и
закрыты тестом `tests/test_scenarios.py`.

Backtest прогноза серы на test (253 анализа, горизонты 0/1/2/3 ч), RMSE, мг/кг:

| Модель | h=0 | h=1 | h=2 | h=3 |
|---|---|---|---|---|
| сдвинутый persistence (выбран) | **2.2955** | **2.3788** | **2.4088** | **2.3708** |
| persistence | 2.6203 | 2.8562 | 2.9211 | 2.7618 |
| ridge по телеметрии | 168.22 | 143.10 | 213.76 | 254.46 |

Каждая строка `build/forecast_report.csv` подписана `evidence_type: backtested`
— это ошибка прогноза на отложенной истории, а не подтверждение эффекта
действия. Все действия в сценариях подписаны `simulated_unvalidated`.

## Как протестировать

```bash
pytest -q                                   # весь набор: 336 passed (с телеметрией и build/)
pytest -q tests/test_hard_constraints.py tests/test_spec.py   # жёсткие ограничения отдельно
pytest -q tests/test_agents.py -k "evidence_type or backtested"  # подпись у каждого вывода
python scripts/scenario_stable.py --role quality   # одна роль одного сценария (пишет только свой файл)
```

CI (`.github/workflows/tests.yml`) прогоняет то же на Python 3.12 без
телеметрии: зависящие от неё тесты пропускаются, а не падают.

`build/lims_pak_long.csv` — единый long-format: `timestamp` (отбор/измерение),
`available_at` (ЛИМС: +4 ч; ПАК: без задержки — допущение), `unit_declared` /
`unit` / `unit_basis` (нормализация единиц, ADR-005), `value`. Единицы серы:
ЛИМС продукта — мг/кг, ПАК — ppm = мг/кг, сырьё — % масс. (×10⁴).
`build/tag_map.csv` — 172 тега, для ВАК — формулы с поправками организаторов
и статусом проверки. Часовой пояс источников общий, но не назван.

## Ограничения

Полный перечень с доказательствами — [ADR-019](docs/adr/019-predeadline-audit.md),
«Последствия», и ADR по ссылкам. Главное:

- **Состав блендинга модельный** (ADR-004, ADR-013): рецептур и спецификации в
  пакете нет. Текущая доля прямогонного компонента 0.0074 % и его цена 0.85 —
  допущения; печатаются как `[MOCKED: …]`. Сера, T95 и плотность компонента —
  измерения точки «Гидроочистка.1»; цетановое число компонента (45) — допущение.
- **Единицы P8/T11/F19 не подтверждены** (ADR-007): уставки показываются как
  сигналы. Влияние уставок на серу (Ridge) проиграло baseline, на T95/ЦЧ не
  моделируется — все `setpoint`-кандидаты отклоняются (`unvalidated_effect_model`,
  `unmodelled_spec_effect`). Ridge обучается на цели с выбросами до 2120 мг/кг
  и вырожденных age-признаках — его RMSE 168–254 отражает и это.
- **Класс риска `high` почти всегда**: порог в единицах backtest-RMSE
  (2.41 мг/кг) при медианном запасе 1.37 мг/кг; сценарии 1 и 2 неразличимы
  по классу риска, различимы по числам.
- **ПАК не входит в прогноз** (ADR-009): задержка публикации не подтверждена,
  хотя корреляция ПАК–ЛИМС 0.48 против −0.004 у соседних ЛИМС. При устаревшем
  ЛИМС система отказывается, а не деградирует до ПАК.
- **Пределы T95 ≤ 360, ЦЧ ≥ 51, плотность 820–845** — летний ряд ГОСТ Р 52368
  как параметры сценария; автопереключения на зимний нет (ADR-015).
- Температура вспышки, отгоны при 250/350 °C, цетановый индекс не проверяются
  (ADR-016); полиароматика, вязкость и др. в пакете не измеряются.
- **Стадия АВТ не моделируется**: `avt_tags.csv` используется только для
  сверки справочника; реализована цепочка гидроочистка → блендинг.
- Выпуск и энергозатраты не моделируются (нет подтверждённых единиц расходов и
  прямых тегов потребления); Парето-фронта нет — бинарная допустимость и один
  критерий выбора; dashboard нет.
- Все моменты выдачи лежат внутри test-окна, по которому посчитана RMSE.
- Детектор аномалий: лабораторная сера — полоса p01–p99 и физичность; ПАК —
  залипание ≥ 1 ч; телеметрия — маркер 307.0, залипание ≥ 6 строк, останов
  T11 < 50 (ADR-014, ADR-018, ADR-019).
