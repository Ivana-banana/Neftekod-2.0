# ADR-006: точка отсечения train/test по времени

## Статус
Принято — зафиксировано до обучения моделей.

## Контекст
ТЗ (§6) запрещает случайное перемешивание строк временного ряда. Точку
отсечения нужно выбрать до подбора моделей: выбранная в конце, «когда метрика
уже видна», она перестаёт что-либо доказывать.

Что известно из отчёта покрытия (`build/coverage_report.md`,
`neftekod.coverage`):

- телеметрия: 2023-01-01 … 2026-08-07, 10-минутный шаг, 189 217 точек;
- `24-2000:Mg.Sulfur` (ПАК, сера): 2023-01-01 … 2026-08-11, непрерывно;
- `24-2000:D15` (ПАК, плотность): **только с 2025-03-05** — раньше показателя
  физически нет;
- `LIMS:Гидроочистка.2.Mg.Sulfur` (лабораторная сера, контрольный факт):
  1462 значения, 2023-01-01 … 2026-08-09, ≈ 400 в год.

## Решение

| Период | Границы | Назначение |
|---|---|---|
| train | 2023-01-01 … 2025-12-24 включительно | обучение |
| embargo | 2025-12-25 … 2025-12-31 | зазор, ничего не используется |
| test | 2026-01-01 … конец данных | отложенная проверка |

Константы — `TRAIN_END`, `TEST_START`, `EMBARGO_DAYS` в
`src/neftekod/config.py`; разбиение делает `neftekod.splits`, тест
`tests/test_time_split.py` не даёт границам разъехаться.

Внутри train для подбора гиперпараметров выделяется валидация
2025-07-01 … 2025-12-24 — тестовый период на настройку не смотрит ни разу.

Обоснование границы 2026-01-01:

1. Тест содержит `24-2000:D15`, доступный только с 2025-03-05. Отсечка раньше
   марта 2025 оставила бы в обучении признак, которого в тесте нет, — или
   наоборот, и сравнение перестало бы быть честным.
2. В train `24-2000:D15` остаётся ≈ 10 месяцев (2025-03-05 … 2025-12-24) —
   достаточно, чтобы признак вообще имел историю.
3. Тест ≈ 7,3 месяца: 253 лабораторных измерения серы, ~31,8 тыс. значений
   поточной серы — хватает, чтобы отличить работающий прогноз от случайного.
4. Граница по календарю (1 января), а не «последние N%», — при обновлении
   выгрузки организаторами точка отсечения не поедет вслед за длиной файла.

Зазор в 7 суток: максимальное окно агрегирующего признака ограничено 7 сутками
(`FEATURE_MAX_WINDOW_DAYS`). Без зазора признак, посчитанный на первой точке
теста по окну в неделю, включил бы данные из train — формально сплит по
времени, фактически утечка на стыке.

## Последствия
Тестовый период не покрывает сезон холодного пуска зимы 2023 и 2024 годов:
низкотемпературные показатели (`CFPP`, `CloudPoint`, `PourPoint`) в тесте
представлены только январём — мартом 2026. Отчёт о качестве прогноза по этим
показателям обязан оговаривать, что проверка сделана на одном зимнем периоде.

Граница зафиксирована и не подбирается по результатам. Если её придётся
сдвинуть, это отдельная запись в этом ADR с указанием причины — не тихое
изменение константы.
