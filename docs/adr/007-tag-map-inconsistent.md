# ADR-007: справочник тегов «КИП» не согласуется сам с собой и с данными

## Статус
Открыт — блокирующий вопрос к организаторам.

## Контекст

Проверка формул ВАК (ADR-002) вывела на более глубокую проблему: сопоставление
«описание из справочника ↔ колонка в телеметрии» не выдерживает проверки на
самих данных. Проверка сделана без обращения к целевой величине (target-blind),
поэтому её результат не может быть следствием подгонки под метрику.

Первое: буква в коде тега не соответствует типу величины. `T12` — «расход
бензина c установки», `W7` — «поточный анализатор содержания серы», `P13` —
«качество продукции по S». То есть `T`/`F`/`W`/`P`/`Q` — сквозная нумерация
псевдонимов, а не мнемоника прибора. Само по себе это нормально для
обезличенной выгрузки и уже отмечено в `CLAUDE.md`.

Второе, и это уже дефект: в справочнике есть пары кодов с дословно совпадающим
описанием, но данные под ними — разные величины.

| Установка | Коды | Общее описание | Медианы | Отношение | corr |
|---|---|---|---|---|---|
| 24-2000 | `F1`, `T12` | Расход бензина c установки | 3.64 / 185.77 | 51.0 | **+0.547** |
| 24-2000 | `F17`, `T23` | Расход ГОДТ в цех №8 | 264.57 / 235.17 | 0.9 | **+0.688** |
| АВТ | `F68`, `F69` | Расход гудрона с установки | 22.97 / 51.26 | 2.23 | **+0.288** |
| АВТ | `F56`, `F57` | Расход фракции до 350 с установки | 28.62 / 33.39 | 1.17 | +0.997 |

Если описание верно, пара описывает один поток и даёт corr ≈ +1 при отношении,
равном переводному множителю единиц. Последняя строка — как должно быть:
`F56`/`F57` при corr +0.997 действительно один поток с двух приборов, дефекта
там нет. Первые три строки этому не удовлетворяют: как минимум одно описание в
каждой из этих пар неверно.

Критерий дефекта — расхождение в данных, а не сам факт дублирующегося
описания.

Третье: пара «массовый / объёмный расход сырья» не даёт физичной плотности.
`T11` («расход сырья на установку, массовый») / `F26` («расход сырья на
установку, объёмный») = **1.414** при физичном для нефтяного сырья диапазоне
0.80…0.93 т/м³. При этом corr(`T11`, `F26`) = +0.839 — похоже на один поток, но
объявленные единицы с ним не сходятся.

Воспроизводится: `neftekod.tag_map.duplicate_descriptions()`, тесты
`tests/test_tag_map.py::test_duplicate_descriptions_are_reported` и
`::test_duplicate_description_pairs_disagree_in_telemetry`.

## Решение

Описания тегов листа «КИП» не считаются подтверждённым источником физического
смысла колонки. Пока организаторы не подтвердят сопоставление:

1. Ни одна модель и ни одна жёсткая проверка не строится на предположении, что
   конкретная колонка телеметрии означает то, что написано в справочнике.
2. Любое использование описания тега сопровождается ссылкой `# см. ADR-007` на
   месте применения.
3. Единицы измерения тегов «КИП» остаются неизвестными (`unit = None`, см.
   `tags_without_unit()`) — отношение 1.414 показывает, что вывести их из
   пары «массовый/объёмный» тоже нельзя.

Вопрос организаторам формулируется с этими числами, а не как «справочник
выглядит странно»: какие из пар `F1`/`T12` и `F17`/`T23` описаны верно и в
каких единицах даны `T11` и `F26`.

## Последствия

Это более сильный блокер, чем ADR-002. Неверные формулы можно заменить
собственной моделью; неверное сопоставление колонок обесценивает любую модель
на этих данных, включая собственную, — она обучится на реальных зависимостях,
но интерпретация («что рекомендовать оператору») будет отнесена не к тому
аппарату.

Прямое следствие для ADR-002: подбирать масштаб отдельного входа формулы ВАК
бессмысленно, пока не подтверждено, что вход вообще тот. Восстановление
масштаба закрыто как направление.
