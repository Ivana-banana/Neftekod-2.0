# ADR-009: синхронизация телеметрии с ЛИМС и ПАК

## Статус

Принято и реализовано 2026-09-10. Метрики остаются backtested; эффект
изменения управляющих воздействий не подтверждён историей и имеет статус
simulated_unvalidated только в модельных сценариях.

## Контекст

ЛИМС, ПАК и телеметрия имеют разные частоты и неполное покрытие. Сопоставление
по номеру строки может связать измерения разных моментов. Для ЛИМС дополнительно
нужно учитывать консервативную оценку публикации timestamp + 4h; для ПАК
доступность в текущей выгрузке принимается равной времени измерения по
явному допущению.

Организаторы подтвердили управляющие переменные гидроочистки P8, T11 и
F19, но не сообщили их единицы и физический масштаб. См. уточнения
организаторов и ADR-007.

## Решение

neftekod.features.synchronize_features() строит признаки as-of для каждого
issue_time:

- ЛИМС и ПАК выбираются только при timestamp <= issue_time и
  available_at <= issue_time; точная граница доступности разрешена.
- Для каждого из P8, T11, F19 берётся последнее конечное измерение
  timestamp <= issue_time - telemetry_lag_hours.
- Нечисловые, NaN и ±inf значения не используются; если предыдущего
  конечного измерения нет, сохраняются *_missing=True и пустое значение.
- Интерполяция через пропуски не выполняется. Timestamp и возраст каждого
  источника сохраняются отдельно.
- Отсутствующий или некорректный available_at у ЛИМС/ПАК — ошибка схемы,
  а не нулевая задержка.

В forecast.evaluate_forecasts() проверяются лаги 0–3 часа. Для каждого лага
alpha выбирается на valid после обучения на fit; затем лаг выбирается по
valid с детерминированным приоритетом меньшего лага при равенстве. На test
оценивается только выбранный лаг, а persistence остаётся неизменным baseline.

Из-за неизвестных единиц P8, T11, F19 Ridge стандартизирует числовые
сигналы средним и стандартным отклонением, вычисленными только на fit.
Пропуски телеметрии импутируются fit-медианой, а индикаторы пропуска остаются
отдельными признаками. Это модельное допущение; оно не превращает сырые
значения в физические единицы и не задаёт промышленный диапазон.

## Последствия

Результат прогнозирования можно честно сравнить с persistence на отложенной
истории и показать возраст использованных анализов/сигналов. Сравнение лагов
не подглядывает в test при выборе.

Точность физической интерпретации P8, T11, F19, качество их измерений и
промышленные диапазоны остаются не подтверждены. Синхронизация не доказывает,
что изменение этих параметров даст измеренный эффект в будущем. T95 не
используется: соответствие лабораторной точки Pipeline по-прежнему не
подтверждено (ADR-003).
