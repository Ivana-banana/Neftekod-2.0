# ADR-014: контроль качества входа — отдельная проверка аномальности анализа

## Статус

Принято 2026-09-12.

## Контекст

Самооценка (`docs/internal/self_assessment.md`, §1) назвала это пробелом номер один по
критерию «Работа с данными»: отдельного детектора аномалий нет, аномалии
отсекаются побочно — порогами устаревания и перцентильными полосами. Это не
одно и то же. Выброс ЛИМС **2120 мг/кг** внутри обучающей выборки не помечен
ничем: он просто не попадает в полосы p01–p99 и p05–p95, и никакой агент об
этом не сообщает.

Отдельная сложность: система должна отличать «значение выходит за диапазон
обучения» (вопрос о том, экстраполирует ли модель) от «значению нельзя
верить» (вопрос о том, годится ли оно как основание действия). До сих пор оба
вопроса отвечались одной проверкой.

## Решение

Проверка называется своим именем (`src/neftekod/anomaly.py`), её результат
публикуется агентом качества в поле `input_anomaly` и попадает в карточку
оператора. Два машиночитаемых кода:

- `nonphysical` — неположительная сера. Это дефект измерения или выгрузки, а не
  чистый продукт;
- `outside_training_band` — значение вне полосы **p01–p99 обучающей выборки**.
  Для цели `LIMS:Гидроочистка.2.Mg.Sulfur` это 2.898–17.308 мг/кг
  (`context.json → training_stats.lims_value`, 1200 обучающих значений при
  min 1.0 и max 2120.0 — то есть буквальные min/max действительно ничего не
  ограничивают).

Порог намеренно взят тот же, по которому агент качества решает «вне диапазона
обучения»: заводить второй порог для той же величины значило бы иметь два
разных ответа на один вопрос. Полоса — модельное допущение по истории, а не
норматив (ТЗ, §4, «Правило границ»).

### Что система делает с флагом

Помеченный анализ **не** приводит к отказу от прогноза: прогноз выдаётся,
потому что оператору нужно видеть оценку. Но агент оптимизации не строит на
таком измерении действий: все кандидаты, кроме сохранения режима, получают код
отклонения `anomalous_input`. Сохранение режима остаётся допустимым — «ничего
не менять» при подозрительном измерении безопаснее любого изменения.

Отсутствие значения аномалией не считается: это отдельная ситуация, ею
занимается отказ агента качества (ADR-010, §2).

## Последствия

- В `optimization.json` появился пятый код отклонения: `hard_constraint`,
  `insufficient_margin`, `unvalidated_effect_model`, `regime_inadmissible`,
  `anomalous_input`.
- Правило ADR-011 (окна сценариев выбираются только среди значений внутри
  полосы p05–p95) теперь подкреплено проверкой в самом коде, а не только
  дисциплиной отбора окон: если бы окно попало на выброс, система сказала бы об
  этом сама.
- На трёх окнах флаг не срабатывает (8.4, 9.9, 5.5 мг/кг внутри полосы) — это
  ожидаемо: окна отбирались внутри полосы p05–p95, которая уже полосы p01–p99.
  В сценарии 3 флаг **срабатывает**: последний опубликованный анализ там
  2.7 мг/кг, то есть ниже p01 = 2.898. Вердикт от этого не меняется — агент
  качества и так отказывается по возрасту (179 ч), — но в карточке оператора
  теперь названы обе причины, а не одна. Это и есть польза от отдельной
  проверки: устаревание и недоверие к значению больше не путаются.
- Проверка закрыта тестами `tests/test_anomaly.py`, включая поведение цепочки:
  на аномальном анализе допустим только `hold`.
- Чего проверка не делает: она не ловит аномалию, лежащую внутри полосы
  (например, физически несогласованную пару «чистое сырьё — грязный продукт»),
  и не проверяет телеметрию. Это честная граница текущей реализации.
