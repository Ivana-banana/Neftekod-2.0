# ADR-008: проверка прогноза серы с учётом времени публикации

## Статус

Принято и реализовано 2026-09-10. Это backtest исторических данных; эффект
неслучившихся управляющих действий остаётся simulated_unvalidated.

## Уточнение 2026-09-12 — имеет приоритет над решением ниже

Baseline заменён: вместо persistence используется сдвинутый persistence
(`shrinkage = 0.3`, уровень — медиана обучающей выборки). Отбор — только на
fit/valid, проверка на test — один раз. Обоснование, таблицы отбора и
последствия для порога допустимости действия — [ADR-012](012-forecast-baseline.md).
Persistence остаётся в отчёте как эталон сравнения.

## Решение

Цель — LIMS:Гидроочистка.2.Mg.Sulfur. Для горизонта h часов строка с целью
в момент t получает признаки на момент выдачи t − h. Последний лабораторный
анализ используется только если его available_at ≤ t − h; для ЛИМС это
консервативно timestamp + 4h. Поточная сера ПАК доступна по своему
available_at (в текущем парсере это время измерения — допущение организаторов).

Сравниваются:

1. persistence — последнее доступное лабораторное значение;
2. Ridge — линейная модель на persistence, поточной сере ПАК, возрасте обоих
   значений и индикаторе отсутствия ПАК.

Обучение выполняется на fit, выбор alpha — на valid, итоговое обучение —
на fit + valid, тест — с 2026-01-01 по ADR-006. Горизонты по умолчанию:
0, 1, 2 и 3 часа. Метрики — MAE, RMSE, R²; рядом сохраняются возраст baseline
и доля пропущенного ПАК.

## Наблюдение на текущих данных

На исходных значениях без выбросного фильтра persistence устойчивее Ridge:
редкие лабораторные значения 107, 120 и 2120 мг/кг сильно влияют на обычную
линейную модель. Это не основание удалять строки молча. В отчёте сохраняются
обе модели и их метрики; следующий этап может выбрать устойчивую модель или
явно описать робастное преобразование.

## Проверка

    python scripts/evaluate_forecast.py
    pytest -q

Результаты имеют evidence_type: backtested и не доказывают, что изменение
температуры, расхода или давления дало бы такой же эффект в будущем.
