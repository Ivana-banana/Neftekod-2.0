### Закрыт расхождение с ответом организаторов: T95 и цетановое число

Организаторы назвали обязательными три показателя товарного ДТ; в коде
проверялся один. `grep -rn "T95\|cetane\|цетан" src/` давал одно попадание —
строку формулы ВАК в `formula_corrections.py`. Это был единственный пункт, где
нарушалось прямое указание организаторов, а не отсутствовали данные.

Ключевое, что выяснилось при разборе: **данные есть**. Оба показателя
измеряются в ЛИМС на точке «Гидроочистка.2» — той же, откуда берётся сера
товарного продукта:

| Показатель | Тег | Значений | Медианный интервал |
|---|---|---|---|
| T95 продукта | `LIMS:Гидроочистка.2.95%.T` | 1292 | 1 сутки |
| Цетановое число продукта | `LIMS:Гидроочистка.2.CetaneNumber` | 42 | 29 суток |
| T95 дешёвого компонента | `LIMS:Гидроочистка.1.95%.T` | 1276 | 1 сутки |

Блокировка [ADR-003](adr/003-lims-pipeline-point.md) касается ссылки `Pipeline`
внутри формулы ВАК, а не измерений. Прежняя формулировка README «T95 не
считается» была неверна и исправлена.

Оба показателя реально ограничивают: T95 продукта имеет p95 = 360 °C при
пределе К5 360 °C (на момент выдачи сценария 4 — ровно 360.0, запас нулевой), а
цетановое число в июле 2026 опускалось до 50.0 при минимуме 51.

Сделано (коммит `e8bb901`, [ADR-015](adr/015-spec-t95-cetane.md)):

| Что | Где |
|---|---|
| `check_t95`, `check_cetane_number` безусловно в `validate_recommendation` | `src/neftekod/constraints.py` |
| Разрешение показателей as-of со своим порогом устаревания у каждого и отбраковкой нефизичных значений | `src/neftekod/spec.py` |
| Модели смешения: T95 массовым балансом, ЦЧ — худшая из двух форм | `spec.blend_t95`, `spec.blend_cetane_number` |
| `spec_indicators` в выводе агента качества | `src/neftekod/agents/quality.py` |
| Показатели у каждого кандидата, шестой код отклонения `unmodelled_spec_effect` | `src/neftekod/agents/optimization.py` |
| Независимый пересчёт показателей и сверка пределов оркестратором | `src/neftekod/agents/orchestrator.py` |
| Все три показателя в карточке оператора с запасом и свежестью | `src/neftekod/agents/card.py` |

Две находки, сделанные при реализации, а не при чтении кода:

1. **Нелинейный blend index из ADR-004 не консервативен.** На смеси 55 и 45
   единиц пополам он даёт 50.125 против 50.0 у линейного баланса, то есть
   *выше*. Защитную проверку на оптимистичной из двух оценок ставить нельзя,
   поэтому `blend_cetane_number()` возвращает минимум. Политика заявлена и не
   зависит от того, какая форма окажется верной.
2. **В `LIMS:Гидроочистка.1.95%.T` есть значение 0 °C.** Без отбраковки смесь
   получала бы несуществующий запас по T95. Закрыто тестом, который упадёт,
   если такие значения из выгрузки исчезнут.

### 2. Решение по нулевому запасу T95 в сценарии 4

Измеренный T95 продукта на 2026-04-04 равен пределу (360.0 °C), а у дешёвого
компонента он выше (362 °C), поэтому по массовому балансу смесь с ненулевой
долей оказывается за пределом на 1.5e-4 °C — на четыре порядка ниже разрешения
лабораторного значения (1 °C).

Реализовано строго, без допуска: допуск размером с разрешение измерения
пропускал бы и реальный перебор на 0.9 °C. Следствие — сценарий 4, вероятно,
станет отказом.

Альтернатива существует (явный giveaway margin отдельным решением в ADR;
внешний ориентир прямо советует «не проектировать точно на нормативную
границу»). Но выбирать её **после** того, как виден результат, — это подгонка,
запрещённая `CLAUDE.md`. Решение принимает команда, не ассистент.

Сейчас пространство кандидатов — два компонента без присадки, хотя ADR-004
фиксирует и цену (тонна присадки = 100 тонн ДТ), и модель отклика
`ΔCN = A(1 − e^{-kd})`. Это единственный рычаг, способный поднять цетановое
число, то есть без него отказ по ЦЧ безальтернативен. База процента «до 3 %» и
зависимость эффекта от дозы организаторами не определены — значит параметры
явные допущения с пометкой, как в ADR-013.

→ verify: кандидат с дозой присадки в `optimization.json`, ЦЧ смеси
пересчитано оркестратором независимо, `evidence_type: simulated_unvalidated`,
экономика присадки в карточке справочно и не влияет на допустимость.

### 4. Стадия АВТ как объект управления (~3–4 ч, критерии 1 и 4)

`data/avt_tags.csv` (247 МБ) используется только для сверки справочника КИП:
`features.TELEMETRY_TAGS` — три тега гидроочистки, признаки те же. Реализована
цепочка «гидроочистка → блендинг», а заявленная — «АВТ → гидроочистка →
блендинг». Свойства сырья АВТ входят только через ЛИМС.

Осторожно: организаторы подтвердили как управления гидроочистки только
`P8`/`T11`/`F19`; управления АВТ ими не названы, поэтому любой тег АВТ,
объявленный уставкой, — допущение, и оно требует записи в ADR. Минимальный
честный шаг — ввести признаки АВТ во вход (не рычаги) и проверить, улучшают ли
они прогноз на fit/valid.

→ verify: метрики на valid до и после добавления признаков АВТ; test трогается
один раз; при отсутствии улучшения — записать отрицательный результат, а не
оставить признаки «для вида».

## Границы, действующие на все пункты

- Жёсткие проверки не обходятся нигде, включая «временно, чтобы сценарий показал
  действие». Обязательных показателей три, и запас по одному не покупает
  нарушение по другому.
- Окна сценариев не подбираются под желаемый ответ; test не используется для
  выбора модели, лага, порога или гиперпараметра.
- `backtested` и `simulated_unvalidated` не смешиваются ни в коде, ни в карточке.
- Пороги и допущения меняются только через запись в ADR с обоснованием.
- Ничего не помечается «работает»/«проверено» без приложенного вывода команды.
- Численные пределы, оставленные организаторами команде, подписываются как
  параметры сценария и не выдаются за норматив.

### Дополнения к остатку работ

Вставляются в существующий список по приоритету:

- **после пункта 1** — температура вспышки, отгон при 250 °C и при 350 °C как
  проверки состояния продукта (ADR-016, «Последствия»). Вспышка нарушается на
  выгрузке (p01 = 48.2 при минимуме 55), `I350` требует отбраковки нефизичных
  значений. Модели смешения для них нет: компонент не измеряется, поэтому это
  проверки состояния, а не эффекта действия;
- **к пункту 2** — в самооценку добавить блоки A и B по стандарту из отчёта об
  оценке политик: сейчас блок B существует по сути, но не назван и не несёт
  диагностик overlap и доли решений вне support;
- **к пункту 4** — схемы с позициями дают физический смысл тегов АВТ, то есть
  работа по вводу признаков АВТ стала дешевле, чем оценивалось.

2. **Новое**: плотность не подтверждена свежим анализом в 29.2 % моментов
