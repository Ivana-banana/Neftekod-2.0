## Задача этой сессии

Довести проект до состояния «готов к написанию логики агентов», **не
реализуя саму бизнес-логику МАС** и не трогая функциональность, заблокированную
ADR-001…003 (формулы ВАК и тег `24-2000:Mg.Sulfur.Q` — использовать
`24-2000:Mg.Sulfur` из реального файла с явным логом несовпадения, как
написано в ADR-001; ничего, зависящее от `LIMS:24-2000.Pipeline.*`, не
реализовывать — см. ADR-003).

## Чеклист (по порядку, каждый пункт — с проверкой)

1. **Окружение.** `requirements.txt`/venv (или `pyproject.toml` — выбери и
   обоснуй), базовая структура `src/`, `tests/`, `scripts/` под EDA.
   → verify: установка зависимостей с нуля отрабатывает без ошибок.
2. **Данные на месте.** Подтвердить/скачать `data/avt_tags.csv` и
   `data/242000_tags.csv` (ссылка на Google Drive — в `README.md`, если
   файлов ещё нет локально).
   → verify: `wc -l` на оба файла ≈ 189218 строк.
3. **Парсер lims/pak** по `SKILL.md` → единый long-format
   `(timestamp, tag, value, source)` с полем «первая дата наличия показателя».
   → verify: тест на реальном фрагменте файла (не только синтетика) — см.
   раздел «Тесты и доказательство результата» в `CLAUDE.md`.
4. **Единая карта тегов** — объединить листы КИП+ЛА+ПАК+ВАК из
   `docs/tz/tags_hackathon.xlsx` в один машиночитаемый файл (код → описание → единица
   → источник → установка/точка).
   → verify: число строк совпадает с суммой строк исходных листов; теги без
   единицы измерения помечены отдельно, не пропущены молча.
5. **Отчёт покрытия/актуальности** по каждому лабораторному/поточному
   показателю: первая/последняя дата, число точек, типичный интервал,
   доля пропусков.
   → verify: отчёт явно показывает разрыв по `24-2000:D15` (2023 → 2025) как
   факт данных, а не как баг парсера.
6. **Тег КИП ↔ колонки телеметрии — закрепить тестом.** Совпадение уже
   проверялось вручную (см. переписку с командой), теперь нужен
   тест/скрипт, который не даст этому расхождению тихо появиться при
   обновлении данных организаторами.
7. **Точка отсечения train/test по времени** — выбрать и зафиксировать
   сейчас, с обоснованием (новый ADR или `docs/decisions.md`), а не в конце
   проекта.
8. **`tests/test_hard_constraints.py`** — создать/дополнить каркас (можно с
   `pytest.skip`, пока нет бизнес-логики), чтобы Stop-hook
   (`.claude/hooks/check-hard-constraints.sh`) перестал молча пропускать всё
   по умолчанию.
9. **README.md** — добавить раздел «Как запустить подготовительный
   пайплайн»: одна команда/скрипт от нуля до готового long-format датасета и
   отчёта покрытия.
10. **Не изобретать ответы за организаторов.** Если шаг упирается в
    ADR-001…003 — явно остановиться, оставить TODO со ссылкой на ADR,
    перейти к следующему пункту.
